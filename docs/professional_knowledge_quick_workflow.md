# 专业课知识库快速工作流

这套流程的目标是：换一门专业课时，不改 Python 代码，也能快速建立一个可核对、可恢复、不会重复入库的私有知识库。

## 第一次使用

1. 运行 `启动知识库.bat`，或执行：

   ```powershell
   python -m streamlit run app.py --server.port 8505 --server.fileWatcherType none
   ```

   如果 8505 已被占用，请换一个空闲端口；调试时不要同时启动多个 Streamlit 进程。

2. 进入“专业课学习”界面。
3. 如果列表里没有你的专业课，展开“＋ 新增 / 管理专业课”。填写专业课名称和所考科目；考试代码和抽取重点可以留空。这里不需要、也不会读取本机资料文件夹路径。
4. 第一次使用建议上传目标院校最新考纲。408 会先加载内置学习库，再用学校考纲标记重点；其他专业课会按你填写的所考科目分类。
5. 在左侧“来源”选择“读取大纲”或“添加资料”。“添加资料”支持教材、讲义、真题解析和个人笔记，文件会在后台整理，页面可以继续使用。
6. 资料整理完成后，在下方“知识库”和“高级知识条目管理”查看条目；每个条目可以展开学习、出题、保存题目，并进入“复习挑战”反复练。

## 中途退出怎么办

系统会把以下内容保存到 SQLite：

- 大纲及个人资料的基本信息和处理状态
- 原始提取文本、清洗文本和人工确认文本
- PDF/OCR 处理报告和错误信息
- 剩余草稿、已确认队列和警告

重新打开页面后，已上传大纲和个人资料、后台任务状态及确认过的知识点都会从 SQLite 恢复。工作台入口不需要停在原页面等待；需要看进度时点“刷新整理状态”。

## 新增专业课后保存在哪里

- 内置学科配置：`professional_knowledge/default_subjects.json`
- 页面向导创建的个人配置：`data/config/custom_subjects.json`
- 私有知识库和工作流状态：`.env` 中 `MEMORY_DB` 指向的 SQLite 文件
- 用户上传的大纲和个人资料文件：`data/user_materials/<user_id>/`

个人配置、数据库和用户上传文件默认不提交到 Git。

当前 `custom_subjects.json` 对同一个部署实例全局生效；如果未来开放给多个互不信任的用户，需要再增加管理员权限和按用户隔离的学科配置表。

## 学科配置能控制什么

每门专业课使用同一份配置统一控制：

- 页面名称与启用状态
- 每次最多抽取的知识点数 `max_points`
- 学科抽取重点 `extraction_guidance`

长资料的分块数超过知识点额度时，系统会均匀覆盖全文的首段、中段和末段，并明确提示本次没有逐段处理的数量。

## 当前边界

本轮优先保证“内置知识库、后台整理、资料问答、题目练习、批改反馈、复习记录”闭环。以下能力留到后续迭代：

- source chunks 页级/题级事实库
- FTS5 与向量混合检索
- 可视化知识关系图
- 更完整的后台队列和跨进程任务调度
- MinerU 等复杂版面解析

在当前闭环稳定前，不建议先叠加这些组件。
